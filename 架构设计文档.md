## 2. 技术栈选型

### 2.1 总体选型

| 层级 | 选型 | 版本 | 选型理由 |
|------|------|:---:|------|
| **前端框架** | React | 18.x | 生态成熟，社区活跃，SSE处理方案丰富 |
| **前端语言** | TypeScript | 5.x | 类型安全，降低大型项目维护成本 |
| **UI 组件库** | Ant Design | 5.x | 企业级组件丰富，支持响应式，中文友好 |
| **状态管理** | Zustand | 4.x | 轻量无模板代码，TS支持好，比Redux简洁 |
| **构建工具** | Vite | 5.x | 开发热更新快，生产构建优化好 |
| **后端语言** | Python | 3.11+ | ML/AI生态最成熟，LangChain原生支持，开发效率高 |
| **后端框架** | FastAPI | 0.115+ | 异步高性能，自动API文档，SSE原生支持 |
| **LLM 框架** | LangChain | 0.3+ | RAG链式调用、Prompt模板、多模型适配、流式输出 |
| **数据库驱动** | Motor (Async) | 3.6+ | MongoDB 异步驱动，与 FastAPI 协程模型天然匹配 |
| **知识检索平台** | RAGFlow | v0.15.0 | 开箱即用的 RAG 引擎，内置文档解析/向量化/混合检索 |
| **数据库** | MongoDB | 7.0 | 文档模型灵活，JSON与API直接映射，水平扩展方便 |
| **LLM 模型** | DeepSeek Chat | latest | 中文法律领域理解力强，性价比高，支持128K上下文 |
| **向量存储** | RAGFlow内置 (ES + FAISS/Infinity) | - | RAGFlow内置检索引擎，无需单独维护向量数据库 |
| **反向代理** | Nginx | 1.25+ | 高性能，支持SSL终结、限流、负载均衡 |
| **容器化** | Docker + Compose | latest | MongoDB + RAGFlow + Python服务统一编排 |
| **CI/CD** | GitHub Actions | - | 与代码仓库集成紧密，免费额度充足 |
| **监控** | Prometheus + Grafana | latest | 开源标准监控方案，生态完善 |
| **部署平台** | Alibaba Cloud ECS | Ubuntu 22.04 LTS | 国内云服务稳定可靠，合规要求满足

### 2.2 备选方案

| 场景 | 主选 | 备选 | 切换条件 |
|------|------|------|------|
| 前端框架 | React | Vue 3 | 团队Vue经验更丰富时切换 |
| UI组件 | Ant Design | TDesign | 需要腾讯云生态统一时 |
| 后端框架 | FastAPI | Django Ninja | 需要更完整的ORM和Admin时 |
| LLM框架 | LangChain | LlamaIndex | LangChain文档不满足需求时 |
| 知识检索 | RAGFlow | Dify | RAGFlow部署复杂度超出预期时 |
| 大模型 | DeepSeek | 通义千问/Qwen | API不可用或质量不达标时 |
| 数据库 | MongoDB | PostgreSQL | 需要强事务一致性或复杂JOIN时 |

### 3.2 核心设计决策

| 决策点 | 方案 | 理由 |
|------|------|------|
| 状态管理 | Zustand | 比 Redux 轻量，TS 推导好，学习成本低 |
| 路由懒加载 | React.lazy + Suspense | 按页面拆分 bundle，降低首屏体积 |
| SSE 消费 | EventSource + 自定义 Hook | 原生支持重连，比 WebSocket 更轻 |
| Markdown 渲染 | react-markdown + rehype-sanitize | 安全渲染（防XSS），支持 GFM 语法 |
| 虚拟列表 | react-virtuoso | 长对话消息列表性能优化 |
| CSS 方案 | CSS Modules + CSS Variables | 设计Token用变量，组件样式隔离用Module |
| 错误边界 | React ErrorBoundary | 每个页面包裹，防止单页崩溃影响全局 |

### 4.3 核心模块设计

#### 4.3.1 用户鉴权流程

```
注册:  手机号 + 验证码 → 验证码校验 → 创建/查找用户 → 签发 JWT Token → 返回
登录:  手机号 + 验证码 → 验证码校验 → 查找用户 → 签发 JWT Token → 返回
刷新:  Refresh Token → 校验 → 签发新 Access Token → 返回
鉴权:  Authorization: Bearer <token> → JWT解析 → 用户信息注入 Context
```

- Access Token 有效期：24小时
- Refresh Token 有效期：7天
- Token 含：user_id、phone(脱敏)、issued_at
- 验证码有效期：5分钟，同手机号60秒内不可重发

#### 4.3.2 流式对话流程

```
1. 鉴权校验 → 限流检查
2. 保存用户消息到 MongoDB
3. 调用 RAGFlow 检索 API → 等待 Top-K 法条
4. LangChain 拼接完整 Prompt 上下文
5. LangChain DeepSeek Chat 流式调用
6. 边接收边转发 SSE 到前端（每个 chunk 直接透传）
7. 流结束后：
   - 保存完整 AI 回复到 MongoDB
   - 记录法条引用关联
   - 更新 Token 消耗统计
```

#### 4.3.3 限流与熔断

```
限流策略: 滑动窗口算法 (内存实现)
  - 每用户每分钟 10 次消息发送
  - 每 IP 每分钟 30 次请求
  - 基于 FastAPI 中间件 + collections.deque 实现

熔断策略:
  - 连续失败 5 次 → 熔断器打开(30s)
  - 半开状态：允许 1 次尝试
  - 成功 → 关闭；失败 → 重新打开
  - 基于 tenacity 库实现

重试策略:
  - 指数退避：1s → 2s → 4s (最多3次)
  - 仅对 5xx 和网络错误重试
  - 4xx 错误不重试
```

### 5.3 内嵌文档 vs 引用策略

| 场景 | 策略 | 说明 |
|------|:---:|------|
| 消息 → 法条引用 | **内嵌** (law_refs 数组) | 法条引用与消息强绑定，内嵌可避免 JOIN，一次查询获取完整数据 |
| 会话 → 消息 | **引用** (session_id) | 消息量可能很大，适合独立存储 |
| 用户 → 会话 | **引用** (user_id) | 用户与会话为典型的一对多关系 |

### 5.4 无缓存架构说明

由于不引入 Redis，以下能力通过 MongoDB 内建机制实现：

| 原缓存场景 | MongoDB 替代方案 |
|------|------|
| 会话缓存 | MongoDB 查询性能足够，无需缓存层；利用索引 + 连接池 |
| 限流计数 | FastAPI 中间件 + 内存 collections.deque（单进程） |
| 短信发送频率限制 | sms_codes 集合查询（利用 phone + created_at 复合索引） |
| Token 黑名单 | 在 JWT payload 中设置短有效期（24h），不做服务端黑名单 |
| 熔断器状态 | 内存变量维护（单进程场景），多进程可通过 MongoDB 读写 |

### 7.2 System Prompt 结构

```
[系统角色]
你是一名专业的AI法律助手，基于权威法律法规为用户提供法律信息参考。
你必须严格基于检索到的真实法条回答问题，不得虚构或编造法律条文。
你没有律师执业资格，你的回答不构成法律意见。

[回答格式要求]
你必须按照以下结构组织回答：
1. **问题分析**：简要分析用户提出的法律问题涉及的法律关系
2. **法律依据**：列出相关的法律法规（必须使用格式 `《法律名称》第X条第Y款`，并引用原文）
3. **建议/结论**：基于法律依据给出初步建议
4. **风险提示**：固定附带以下声明

[法条引用规范]
- 只引用检索结果中实际返回的法条
- 引用格式：《法律全称》第X条第Y款
- 如果检索结果中没有相关法条，请明确告知用户"未检索到相关法条"
- 不得自行编造法律条文、不得虚构条款号

[禁止行为]
- 不得预测判决结果
- 不得提供法律代理建议  
- 不得教唆用户采取违法手段
- 不得回答与法律无关的问题
- 不得提供具体法律文书的起草服务（可以说"建议咨询律师起草"）

[拒答规则]
以下情况直接拒答：
- 涉及危害国家安全、煽动暴力、教唆犯罪
- 要求AI扮演律师或法官角色
- 提问超出法律咨询范畴（如医疗建议、心理咨询）
- 拒答话术："抱歉，您的问题超出了我能回答的范围。建议您咨询相关领域的专业人士。"

[风险提示模板]
---
⚠️ **免责声明**
以上内容仅供参考，不构成法律意见。AI并非律师，回答可能存在误差。
如遇重大法律问题，强烈建议您咨询具有执业资格的律师以获取专业法律建议。
---

[当前对话上下文]
用户问题：{user_query}

[相关法律依据]
{retrieved_laws}

请基于以上信息回答问题。
```

## 8. 安全架构

### 8.1 安全分层

| 层级 | 安全措施 |
|------|------|
| **传输层** | HTTPS 全站；HSTS 头；TLS 1.2+ |
| **接入层** | Nginx 限流（limit_req）；IP 黑名单；WAF 规则（可选） |
| **应用层** | JWT 鉴权；API 限流；输入参数校验；SQL 注入防护（参数化查询）；XSS 过滤 |
| **数据层** | 手机号 AES-256 加密；密码哈希（如有）；数据库连接加密 |
| **基础设施** | 安全组最小权限；SSH 密钥登录；定期漏洞扫描 |

### 8.2 内容安全

```
用户输入 → 敏感词匹配(字典树) → 正则规则 → AI内容审核(可选)
    │            │                  │
    ▼            ▼                  ▼
  放行       拦截+记录日志       人工复核队列

AI回复 → 法条引用真实性校验 → 合规声明完整性检查 → 敏感内容二次过滤
```

### 8.3 数据加密

| 数据 | 加密方式 | 密钥管理 |
|------|------|------|
| 用户手机号 | AES-256-GCM | KMS / 环境变量 |
| JWT Token | HMAC-SHA256 | 环境变量 |
| 用户密码（如有） | bcrypt (cost=12) | - |
| 数据库连接 | TLS + 密码 | 环境变量 / Vault |
| 备份文件 | AES-256 加密后存储 | KMS |

### 10.1 监控指标体系

| 层级 | 指标 | 告警阈值 |
|------|------|:---:|

| 数据库 | 连接数 > 80%，慢查询 > 5s，副本集延迟 > 10s | P1 |

| 大模型 | 调用成功率 < 95%，P95延迟 > 15s | P0 |
| Token消耗 | 日消耗超过预算 80% | P2 |
| 业务指标 | 消息发送成功率 < 99%，流式中断率 > 5% | P0 |
