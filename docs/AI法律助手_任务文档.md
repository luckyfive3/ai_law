## 1. 项目概述与原型页面分析

### 1.1 产品定位

面向普通公众的 **AI 智能法律咨询服务工具**，用户通过自然语言对话方式提出法律问题，系统基于权威法律知识库 + 大模型生成专业、合规的法律建议回复。核心价值：降低法律咨询门槛，提供便捷、可靠的基础法律指导。

### 1.2 技术架构概要

```
用户浏览器 → Nginx(HTTPS) → 前端SSR(FastAPI+Jinja2) / 后端API(FastAPI)
                                    ↕
                  后端服务 (Python FastAPI + LangChain)
                  ├── JWT 鉴权 + 限流 + 内容安全
                  ├── 业务逻辑：用户 / 会话 / 消息 / 知识库
                  ├── LLM 调用：LangChain + DeepSeek Chat API
                  └── 知识检索：RAGFlow HTTP API
                                    ↕
              MongoDB 7.0 (数据持久化)    RAGFlow v0.15.0 (向量检索+知识库)
```

| A1-1.3 | 语料分段 | 按法条自然段落切分（每条法条为一个 chunk），对长法条按"条-款-项"层级切分；每个 chunk 长度控制在 500-1500 字符，确保语义完整性；增量更新策略设计（法律修订后局部替换） | 分段后语料，含 chunk_id、原文、来源、层级 |

| A1-1.6 | 合规审核 | 确保语料来源合法合规、不含侵权内容；敏感政治类法律条文按合规要求标注处理策略 | 合规审核记录 |

## 9. 跨岗位协作接口清单

### 9.1 前端 ↔ 后端接口

所有接口遵循统一的 `{code, message, data}` 响应格式。前端通过 API 代理（前端 3000 端口 → 代理至后端 8080 端口）访问。

| 接口 | 方法 | 路径 | 说明 | 优先级 |
|------|:---:|------|------|:---:|
| 用户注册 | POST | `/api/v1/auth/register` | 用户名+密码+协议勾选注册 | P0 |
| 用户登录 | POST | `/api/v1/auth/login` | 用户名+密码+协议勾选登录，返回 JWT Token | P0 |
| 刷新Token | POST | `/api/v1/auth/refresh` | 使用 Refresh Token 刷新 Access Token | P1 |
| 退出登录 | POST | `/api/v1/auth/logout` | 退出登录（JWT无状态客户端清除） | P1 |
| 创建会话 | POST | `/api/v1/sessions` | 创建新对话会话（可选 title/category） | P0 |
| 获取会话列表 | GET | `/api/v1/sessions` | 分页获取历史会话（按时间降序） | P0 |
| 获取会话详情 | GET | `/api/v1/sessions/{id}` | 含会话元信息和分页消息列表 | P0 |
| 删除会话 | DELETE | `/api/v1/sessions/{id}` | 软删除（status=0） | P1 |
| 清空全部历史 | DELETE | `/api/v1/sessions/clear-all` | 软删除用户全部会话 | P2 |
| 发送消息（SSE流式） | POST | `/api/v1/chat/stream` | SSE事件：thinking/chunk/law_ref/done | P0 |
| 获取消息列表 | GET | `/api/v1/chat/{session_id}/messages` | 分页获取会话消息（含法条引用） | P0 |
| 导出对话 | GET | `/api/v1/chat/{session_id}/export` | 导出为纯文本文件 | P2 |
| 获取用户信息 | GET | `/api/v1/user/profile` | 用户基本资料 | P1 |
| 更新用户信息 | PUT | `/api/v1/user/profile` | 更新昵称/头像 | P2 |
| 更新隐私设置 | PUT | `/api/v1/user/privacy` | 设置是否保存历史记录 | P2 |

### 9.2 后端内部服务调用

> **注意**：v2.0 架构简化——后端不再通过中间微服务调用算法侧，而是直接在 Service 层调用外部平台 API。这消除了内部接口约定的协调成本。

| 调用 | 方向 | 说明 | 优先级 |
|------|:---:|------|:---:|
| RAGFlow 检索 | 后端 Service → RAGFlow HTTP API | POST `/api/v1/retrieval`，传入 query + dataset_id，返回 Top-K 法条（law_name/article_num/law_text/similarity） | P0 |
| DeepSeek LLM | 后端 Service → DeepSeek API | LangChain `ChatOpenAI` 封装，POST `/v1/chat/completions`（通过 base_url 指向 DeepSeek），支持流式（`stream: true`） | P0 |

> 2. 数据库从 PostgreSQL + Redis 切换为 **MongoDB 7.0**（文档模型天然匹配对话数据，异步驱动性能足够）
> 3. 检索系统从自建 Milvus/Qdrant 切换为 **RAGFlow v0.15.0**（开箱即用的 RAG 平台，免去向量库运维）

> 5. 消除了"后端↔检索服务"和"后端↔大模型网关"两个内部微服务接口，降低架构复杂度
